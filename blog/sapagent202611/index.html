AI Agent＋SAP：從 MCP 請購單到 RFC 網關整合

By Jason Li 18 November 2026

AI Agent 要處理 SAP 業務，需要能找到適合的函數、理解欄位，並取得可驗證的執行結果。2026 年的工作從 MCP 請購單 POC，延伸到 sapFDE 的通用 RFC 網關整合。

已完成的整合與驗證

截至 2026/11/18，完成以下實測工作：

  • 連線基礎：以 uv 管理 Python 3.11、固定 PyRFC 版本及 SDK 載入設定；直接 SAP RFC 登入、ping 與 STFC_CONNECTION 回傳驗證通過。
  • 開源網關整合：導入 Jack-Liang/sap-for-agents v0.19.0，固定子模組版本、核對執行檔雜湊，建立安裝、啟動與驗證 launcher。/health、/ready 及通用 /api/rfc 驗證通過。
  • SAP 能力探索：在指定名稱範圍查得 603 筆 RFC／BAPI 目錄結果，確認包含請購與採購相關函數；查得 55 個符合條件的自訂透明表。
  • 欄位與資料理解：取得一張訂單交接表的 12 個欄位、DDIC 說明及複合主鍵，完成 100 筆樣本讀取與本機匯出。

我的成果集中在環境建置、網關整合、驗證與 SAP 查詢；網關核心由上述開源專案提供。目錄搜尋的 603 筆是指定範圍結果，100 筆樣本未指定排序，皆不能視為全系統盤點或最新資料。

相容性處理：依 SAP 實際介面調整

現有 SAP 的 RFC_READ_TABLE 缺少網關 /api/table/read 使用的 USE_ET_DATA_4_RETURN 參數，實測出現 RFC_INVALID_PARAMETER。

成功的做法是改由 /api/rfc 呼叫傳統 RFC_READ_TABLE，指定 FIELDS、OPTIONS，從 DATA.WA 讀取資料，並控制欄位總寬度與分隔符。這次完成了可用的查詢方式；網關的自動相容降級仍待開發。

下一步：從工具可用走向業務可交付

本次驗證建立了 Agent 探索 SAP 與讀取資料的基礎。請購單建立及修改未在這次測試中執行；原有 PR API 當次尚未啟動，其健康檢查仍待重跑。

後續將優先處理舊版介面相容、業務欄位及狀態碼確認，再驗證寫入流程的授權、核准、交易回傳與重複執行控制。通用 RFC 網關的 /api/rfc 與既有 PR API 的 /pr/create 是不同契約，串接前必須明確對應。

本文依 sapFDE 的 01工作摘要.md（2026/11/18）、根目錄 README 與子專案操作文件整理，呈現當次驗證成果。
